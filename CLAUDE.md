# penumbra

Figma plugin: a list of layered object shadows per layer, each driven by elevation (the object's gap, shared by all its shadows), one light (direction, distance, start/end softness; linked shadows share its direction; `MAX_LIGHTS` is 1 since several lights per shadow proved buggy, but the model still holds a list), start/end color (optionally linked) and opacity (solved per overlap band, alphas never rising outward), blend mode, up to 32 copies shaped by four curves (distance, blur, opacity, color; cubic Béziers through four movable points, flat beyond their ends); drop or inner; re-editable via stored settings (v7: `{v, shadows}` with `lights` carrying start/end softness, four-point curves and `colorLinked`; v6 curves were two handles and lights one `softness`, v5 had `spacing` and `merge`/`edge`, v4 `angles` plus one distance and softness, v3 one `angle`; `sanitize` reads them all, `fromSpacing` fits the old spacing to a curve).

- The model lives in `src/shadow.ts` and is shared by plugin and UI preview. Keep it that way; never duplicate the math. Linking happens in `applyPatch`/`insertAt` (via `turnLike`), used by both sides.
- The preview's light handle maps distance from the card's center (0 px) to a circle that fits the stage (1000 px, radius min(w, h)/2 − 10) on a log scale, the same in every direction (an ellipse made a wide stage read 1000 px sideways where it read 171 px upwards) (`lightPoint`/`lightAt` in `src/ui.ts`). Drags follow the pointer's movement, not its position, so a handle never jumps; handles are kept across renders so a drag keeps its pointer capture.
- Hidden shadows (`visible: false`) are stored but never drawn: every writer filters on it (`dropEffects`, `innerEffects`). Copy/paste goes through client storage (`clipboard`), so it crosses files; `paste` replaces the selection's shadows, `add` only fills layers without any.
- Copy alphas are solved per overlap band, then made non-increasing outward by pooling the steps in −ln(1 − alpha) (`solve`, pool adjacent violators): otherwise a strong End shows the far copy's whole shape beside the object while the middle stays faint (a real case: 100 → 60 % over 12). Start stays exact; the far end can come out lighter.
- Merge and the hard outline were removed on 2026-10-30 at the author's call ("merge doesn't really work"). `rematchSelection` rewrites the layers they left (and old split overflow) when such a layer is selected.
- `npm test` covers the model. `src/nodes.ts` (what happens to layers) is checked inside a real file: `npm run figma-check`, then run `.test/figma-check.js` with the Figma MCP's `use_figma` in a scratch file. Figma throws on reading a property a node type lacks: guard with `in`.
- Figma draws later effects on top (checked in a file), so copies are written farthest first.
- Figma keeps 8 drop shadows per node (frames, groups and effect styles too) and drops the rest silently; inner shadows and blurs don't count. So up to 8 copies sit on the object; past that, all of them go on one "Shadows" layer (never split between object and layer, at the author's ask), in parts of 8 (`MAX_EFFECTS`). Any new place that writes effects must respect it. Inner shadows have their own cap of 8 (two inner shadows of 8 copies lost the bottom one). Past it, all inner copies go on one "Inner shadows" layer above the object, in the same group: copies of the object with every paint at 0.1% (`FAINT`), 8 inner shadows each. Figma draws no inner shadow without a visible fill, but does at full strength on a fill at 0.1%, and a frame's own inner shadow is drawn over its children just like the overlay (checked 2026-10-31). The user's own inner shadows stay on the object.
- Penumbra owns all drop shadows but only the inner shadows it wrote: `othersThan` matches them against the previously stored settings, so read those before writing new ones.
- The panel shows no explanatory notes (the author: "nobody reads them"); what the plugin can't do comes as a Figma notice from `code.ts`. Elevation and Blending are the first two rows of the Shadow section (they looked messy in the section heads), Count sits in the Copies head, rows are 28 px, and one curve editor (148 px, the unit square in the middle with room around it: `CURVE_REACH_X` 0.25 across, `CURVE_REACH_Y` 0.5 up and down) shows the ramp a select picks: distance, blur, opacity or color (`CURVES` in `src/ui.ts` says what each axis means). Two shadows are about 824 px, under the 880 px cap. Curve handles may sit outside the square on every side; `readHandles` shortens one past the far end along its own line and holds one behind its own end upright, so the curve stays a function and the drawn curve is the applied one.
- The panel has no sliders: every number is a drag-to-change field (`numberField` in `src/ui.ts`). The panel sends its content height and the plugin resizes the window (`resize` message, capped in `src/code.ts`), so it doesn't scroll. In a hidden browser pane `requestAnimationFrame` never fires, so don't hang UI work that must happen on it.
- Plugin-side handlers run through `guard()` in `src/code.ts`: a layer that can't be changed gives a plain notice, not a developer error (Community review rejects those).
- Publishing lives in `PUBLISHING.md` (every value to paste in its own code block); the listing images in `assets/` are rendered from the Figma page "Community assets" with the real shadow code, so remake them there when the look changes.
- Not yet verifiable without Figma desktop: the panel↔plugin messaging, relaunch button, nodechange sync, undo steps.
